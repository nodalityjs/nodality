# Nodality 1.2 – the page, as tools

**18 August 2026 · 1.2.0 → 1.2.1**

1.1 made a page's interaction structure data. 1.2 hands that structure
to an AI agent – without asking you to write it a second time.

```js
let nodes = [
  { op: "morph", chain: [
      { from: "home", to: { Work: "work" } },
      { from: "work", to: { Aurora: "aurora" } } ] },

  { op: "agent-surface", name: "studio", forms: ["contact-form"] },
];
```

That one node derives four tools – `studio_navigate`, `studio_go_back`,
`studio_submit_contact-form` and `studio_read_view` – registers them
through the browser's WebMCP API where it exists, and writes the same
declaration into the page as static data where it does not.

## Why derive rather than annotate

Your page already says what it can do. The morph chain *is* the
navigation graph; a form's fields already declare their types and which
are required. Every other way of exposing tools to an agent restates
that by hand – as JavaScript handlers, or as attributes annotated onto
the DOM – in a second place, where it drifts the first time either
changes.

Nothing here is a router. Between pages an agent already has URLs; what
it cannot reach by fetching is a chain's non-root **views**, which exist
only after a transition. That is the gap this closes.

## Highlights

**Derived, not authored.** Tool schemas are read from your descriptors:
`inputType: "email"` becomes a string with an email format, a picker's
`items` become an enum, a checkbox becomes a boolean, `required: true`
becomes a required property.

**Opt-in, always – and forms are allowlisted.** No node, no surface;
upgrading never decides for you. And no form is exposed unless you name
it in `forms`, because a derived submit tool is an agent *acting* – the
one derived capability with a real side effect.

**Execution goes through the front door.** `navigate` calls the morph
controller's own `goToState`, so an agent's traversal is the user's
traversal: the state pointer moves only on completion, interrupts
restart from the logical state, and `back` unwinds the path taken.

**Errors are repair reports.** A destination that exists but is not
reachable from where the graph currently stands comes back as
`{ ok: false, code: "UNREACHABLE_FROM_HERE", got, valid }` naming what
*is* reachable. A submit missing a required field names the field. An
agent repairs from either in one turn.

**A static declaration, needing no browser support.** Prerendering
writes `<script type="application/json" id="nodality-agent-manifest">`
into each page and gathers every page's declaration into
`agent-manifest.json`. A crawler, an indexer, or an agent deciding
whether to visit at all can read what your site can do without executing
anything. The declaration and the live registration come from one
derivation, so they cannot disagree.

**The spec's own annotations are emitted, not resisted.** Allowlisted
forms are stamped with `toolname`/`tooldescription`, so the annotated
path and the derived path describe one surface.

## Added

- `{ op: "agent-surface" }` with `name`, `forms` and `exclude`.
- `agent-manifest.json` from `nodality prerender`, byte-stable across
  identical builds.
- Validation for the new family: `UNKNOWN_FORM`, `UNKNOWN_STATE`,
  `EMPTY_SURFACE`, with did-you-mean suggestions drawn from the forms
  and states that exist.
- `preview` (MCP) now reports the surface a pair would give an operating
  agent, so a model writing the page sees the tools a model using the
  page will get.
- `normalizeEdges` and the morph handle's `goBack` are exported, so a
  derived `go_back` is the same action as the back button rather than a
  parallel implementation of it.

## Fixed

- **`read_view` returned nothing on live-backend pages** – the very
  pages using the feature. Content hosted inside a canvas is
  deliberately `visibility: hidden`, so reading "what is visible" read
  nothing while navigation worked perfectly. The current view is now
  known from the controller rather than inferred from paint. *(1.2.1)*
- **Text fields submitted nothing.** `TextField` never forwarded `name`,
  so every text input in every Nodality form contributed no value to
  `FormData` – for a person filling it in, not only for an agent.
  `name`, `id` and `required` now reach the input, and `Form` forwards
  its `id` to the rendered `<form>`.
- **Two agent calls in one tick could blank the interface.** A person
  cannot click twice inside a single tick; an agent can, and two
  transitions starting before either had built its pipeline left nothing
  on screen. Traversals are serialised at the agent boundary.
- **`CSS.escape` does not exist in jsdom**, so the build-time pass threw,
  was swallowed, and every prerendered page shipped silently without its
  declaration.

## Notes

Tool registration uses the **WebMCP** browser API – a W3C Community
Group draft under an origin trial, available in Chrome behind
`chrome://flags/#enable-webmcp-testing` and in Edge behind a flag. It is
not a ratified standard and it has already moved its entry point once
(`navigator.modelContext` → `document.modelContext`); both are
feature-detected, and everything spec-shaped lives in one adapter pinned
to the 2026-07-21 draft. Where the API is absent nothing registers,
nothing warns, and your page behaves identically. **The manifest is
written either way** – that half needs no browser support at all.

Only the **root** view of a morph chain appears in prerendered HTML; the
other states are held until they are transitioned to. Put a form you want
annotated at build time outside the graph.
