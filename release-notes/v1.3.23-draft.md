## `cursor` shows a pointer

`"hand"` is Internet Explorer's name for the pointer cursor. Every other
browser rejects it and keeps the default arrow. The library wrote it in three
places:

- **Text's `cursor` option** set `"hand"` for any truthy value, so
  `cursor: true` on `p` or `h1`–`h6` did nothing, although its documentation
  promised a pointer. `cursor: "pointer"` worked only because the shared style
  options had already set it and the browser threw the later `"hand"` away.
- **The mapper's dropdown labels**, ten of them, including the placeholder
  nav's "More", were given `cursor: "hand"` and showed the arrow.
- **`Image.hand()`** set `"hand"`.

The shared style options now read `cursor: true` and `cursor: "hand"` as
`"pointer"` on every element, and pass any other value through. Text no longer
overwrites it. The mapper and `Image.hand()` write `"pointer"`. The validator
accepts `cursor: true`, which it used to report as `BAD_PARAM_VALUE`.

**Visible change:** where a page used `cursor: true`, `cursor: "hand"` or one
of those dropdowns, hovering now shows the pointer the page asked for.

The schema no longer lists `cursor` on `checkbox`. The generator credited it
through Text's by-name read, but checkbox gives its options to Checkbox, and
Checkbox never read them.

Tests: one in `style-options.test.mjs`, failing on 1.3.22 for both the render
and the validator. The placeholder-nav snapshot was re-pinned at +17
characters, which is exactly the label's `cursor: pointer;`. Checked in Chrome:
`CSS.supports("cursor", "hand")` is false there, and all five cases now compute
to the expected cursor.
