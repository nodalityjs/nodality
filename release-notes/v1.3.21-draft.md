# v1.3.21 — draft

> Draft only. Edit freely and paste into the GitHub release; nothing here is published.

## Style with options, not keySet

Since April 2026 every element has taken CSS-named options — `lineHeight`,
`letterSpacing`, `gap`, `boxShadow`, … — through `commonMethods`. Nobody could
tell: the options were applied through a map rather than read by name, so the
schema generator never credited them. `get_schema p` omitted `lineHeight`, and
`validate_nodes` reported working options as `PARAM_NOT_ON_TYPE`, "accepted and
ignored". Pages wrote `keySet` instead. The suitcase site had 1,453 keySet
entries, nearly all for options the library already had.

- **The schema and validator see them.** The map is now `STYLE_OPTIONS` in
  `layout/animator.js`. The generator credits it, plus the options
  `commonMethods` reads by name (`pad`, `mar`, `weight`, `bold`, `borderObj`,
  `respad`, `resmar`), to every type whose element options reach a component
  that runs `commonMethods`. "Reach" means the component that receives the
  options, not any component involved. That is why `checkbox` is not credited:
  it styles its label with Text, but sends the element's options to Checkbox.
  Undocumented options get a plain description: "CSS line-height, written
  verbatim."
- **New options:**
  - `alignContent`, `alignItems`, `justifyContent`, `justifyItems` and
    `justifySelf`;
  - `aspectRatio`;
  - `borderTop`, `borderRight`, `borderBottom` and `borderLeft`;
  - `textDecoration`, `objectFit` and `objectPosition`;
  - `weight` (font weight), now also outside `commonMethods`.
- **The nav bar takes them.** A page nav's bar applies the element's CSS-named
  options, so `backdropFilter`, `boxShadow`, `exact` and `weight` need no keySet.
  `font` and `color` keep their nav meaning: they style the links. Eight `nav`
  options listed as known-inert now work.
- **Commerce elements take them.** `price`, `productData`, `productMedia`,
  `variantPicker` and `buy` take the CSS-named options and `pad`/`mar`, both live
  and in their static copy. Until now only `font`, `color` and `keySet` reached
  them. `store` and `cart` draw nothing of their own and are not offered them.
- **`exact` sizes text.** On `p`, `h1`–`h6` the type's scale step overwrote an
  exact size, so only keySet could size text. An exact size now wins.

## Fixes found on the way

- **`gpos` with one axis broke grid placement.** `gpos: { col: "1 / -1" }` wrote
  `gridRow = undefined`. A browser reads "undefined" as a grid line name, so the
  element moved to an implicit row at the end of the grid. Only the given axes
  are written now.
- **The schema generator overran `sideNav`.** Its method-body scanner lost its
  place in that 300-line mapper and returned the rest of the file. Mapper
  bodies are now capped at the next static method.
- **Did-you-mean prefers dropped letters.** `colr` suggests `color` ahead of the
  equally distant `cols`.
- **The validator's text-sizing hint** suggests `exact`, not keySet.

## Skill

The house rules now say to style with options and keep keySet for a property no
option names.

Tests: `style-options.test.mjs` (9 tests), each run against 1.3.20 first and
failing there. The demo-nav snapshot was re-pinned: same declarations in a
different order. `checkbox.exact` and `sideNav.exact` were recorded as known
inert.

Verified on a real site: the suitcase site, converted from 1,453 keySet entries
to options. All 53,760 captured computed-style values (59 properties and the
box of every id'd element, six pages, 375 and 1280 px) are identical to the
keySet version. The nav bar was compared separately against production.
