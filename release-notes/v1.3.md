# Nodality 1.3 – the page an agent can check

**30 August 2026 · 1.2.11 → 1.3.0**

1.2 made a page's structure available to an agent. 1.3 asks the question that
follows and had never been asked: given a brief, does an agent actually produce
a correct page?

It was measured. A model was run over 24 briefs and scored on four gates –
valid, renders, content, quality – against a hand-written control. That single
number reshaped this release: the format was not the bottleneck, and most of
what follows came from watching where a model actually goes wrong.

## Highlights

**An agent can now see what it made.** `check_page` drives a real browser at
phone and desktop widths and reports horizontal overflow, elements past the
viewport, clipped content, images with no description, tap targets under 24px,
controls with no accessible name, skipped heading levels and text below the
WCAG contrast minimum – in the same report shape `validate_nodes` returns. Up
to now every check in this library looked at the input. A spec could be perfect
and the page still wrong, and nothing would say so.

**HTML's names are accepted.** `src` and `href` both mean `url`; `options`
means `items`. This is not a convenience: four of the seven failures in the
model run were that one mistake. A model writing `src` for an image is not
confused, it is applying the most widely attested convention there is, and the
divergence bought nothing. Accepting it moved first-try success from 17/24 to
21/24 on the model's own unchanged answers.

**Shared structure is declared once.** `.defs({ nav, footer })` plus
`{ $ref: "nav" }` – 61% of every token in a real site was the same nav and
footer repeated, because an element array cannot call a function the way the
imperative layer can.

**The components' own output was measured and fixed.** Correct specs were
producing pages with real defects six times out of ten. Contrast failures,
a heading level that skipped three, tap targets under the minimum, images with
no description. None of it was reachable by the author.

## Added

- **`check_page`** – MCP tool and `nodality/…` module. Playwright is not a
  dependency; its absence is a report naming the install command, as with jsdom
  and `preview`.
- **`tag`** on text elements – heading level independent of size. `size: "S5"`
  used to *be* an `<h5>`, which is fine when a person picks both at once and
  wrong for a generated page, where the outline is structure and the type scale
  is style.
- **`nodality/refs`** – `.defs()` and `{ $ref }`. Worth it from two pages up;
  at one page a reference costs more than writing the thing.
- **`nodality/normalize`** – the alias and shape table, if you want to apply it
  yourself.
- **`label`** on `dropdown` and `labelInput`, which is what every generator and
  every UI kit calls it.
- **Table rows as arrays**, header row first, the way a CSV is laid out.

## Changed – visible on existing pages

This is why 1.3 is a minor and not a patch. Every one of these is a measured
threshold, not a preference, and all of them are overridable through `.set()`.

| | was | now | why |
|---|---|---|---|
| card title | `#f97316` | `#c2410c` | 2.80:1 on white against a 3:1 requirement |
| card link | on `#3498db` | on `#1d6fe0` | white on it was 3.15:1, needs 4.5:1 |
| table header | on `#ff6d22` | on `#c2410c` | 2.81:1 – styled, and not legible |
| hamburger | `#e67e22` / `#1abc9c` | `#c2410c` / `#0f766e` | 2.85:1 and 2.41:1 |
| card title level | `<h5>` | `<h2>` | any page with an `h1` above a grid skipped h2, h3 and h4 |
| nav links, sideNav toggle | 43×18, 40×20 | padded past 24px | WCAG 2.2 AA minimum |
| text fields | `content-box` | `border-box` | width 100% plus padding overflowed the viewport by exactly the padding |

## Fixed

- **`sideNav` rendered a hardcoded link instead of the one you declared.** The
  caller's `link` went into an option `Link` never reads.
- **Card images emitted `<div src="…">`** – invalid HTML that fetches nothing,
  in every generated card grid. They can also carry `alt` now.
- **`dropdown` spent its first item on the trigger label**, so four declared
  options gave three – and setting `title`, the supported way to label one,
  silently ate the first option instead.
- **Prerendered pages shipped an empty nav toggle.** The glyph was set with
  `innerText`, which jsdom has no setter for, and the SSG prerenders through
  jsdom. Invisible in a live browser, wrong in every statically generated site.
- **`npx nodality schema` did not work in an installed package.** `schema.json`
  and the generator were outside `files`, so the subcommand failed with
  MODULE_NOT_FOUND for every consumer while passing every test in the repo.
  Fixed in 1.2.11; the packaging smoke test now runs the subcommand.
- **Two incompatible id conventions.** `animator.js` required `#hero`,
  `morph-node.js` stripped it, and raster targeting matched by exact string –
  so `target: ["#hero"]` reached a raster op not at all. Both spellings now
  match everywhere, normalised at the point of comparison so no existing page
  changes meaning.
- **Descriptors could be recorded against the wrong nodes.** `add` lifts `nav`
  and `sideNav` to the front of the page and the descriptor array was kept in
  the author's order, so anything matching the two by position – morph
  resolving `from`/`to`, and the round-trip – was misaligned whenever a nav was
  declared late.
- **Content in the slot a type does not read** is reported as
  `WRONG_CONTENT_SLOT`, and a content slot that is not a list as
  `BAD_CONTENT_SHAPE`. Both used to validate clean and render the placeholders.

## Notes

**What the numbers are.** Schema on demand is 2.3× to 41× cheaper than carrying
it in context, depending on how much of the vocabulary a page touches. Editing
an existing page beats regenerating it 14.4× on a twelve-card grid. Shared
fragments are 1.26× at two pages and 1.73× at four. Composites authored as data
are 2.09× to 2.63× against React + Tailwind – as code they were 0.94×, below
parity, which is what started this work.

**What is not claimed.** The 24-brief eval was written largely by the same
people who wrote the checks, and the seven briefs derived from an existing
production site are where every remaining failure sits. That split is printed
by the runner rather than hidden. The two failures left are the model's own –
an element with no type, and an omitted string – not the format's.

**Annotation stays off by default.** It costs about 18% of page weight and
compression does not help, because the attributes are the page's own content
repeated as JSON. Turn it on for pages that will be edited.
