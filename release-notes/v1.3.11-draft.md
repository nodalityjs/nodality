# v1.3.11 — draft

> Draft only. Edit freely and paste into the GitHub release; nothing here is published.

## The schema now describes what the library does, not what it mentions

The schema was derived from what components READ. Whether a spec could reach
those parameters is a different question, and nothing asked it. `mapTable` is
the plain case: it builds its own options object with `cellPadding`,
`cellAlign`, `style.font` and `headStyle` hardcoded and never looks at the
element, while `Table` reads all four. The schema advertised them, the
validator accepted them, and the page ignored them.

**772 of 1800 declared parameters — 43% — could not be reached from a spec.**
They are gone. `nav` reported 157 parameters and accepted 5; `dropdown` the
same; `table` reported 24 and accepted 3. `npx nodality schema <type>` now
carries `forwardsElement`, which says whether the mapper hands your options to
its components at all.

## Parameters declare their value shape, and the validator checks it

The validator checked names and never values, so `width: 7`, `mar: 7` and
`columns: "four"` all validated clean and all rendered nothing. Annotations
take a unit — `//@ radius {px-or-length}: …` — and `validate_nodes` reports:

```
BAD_PARAM_VALUE  elements[0].width   got 7
  valid:       a CSS length with a unit, e.g. "320px", "100%" or "2rem"
  suggestions: "7px"
```

An error where the value is provably inert (a bare number where CSS wants a
length, a value outside a declared enum); a **warning** otherwise, so a page
that renders keeps validating.

## `warnings`: the page renders, but not as you wrote it

`validate_nodes` reports a second class of finding, which does not change `ok`:

- `PARAM_NOT_ON_TYPE` — a real parameter name this type does not read.
  `keySet` on a `table` passed before, because the name is real somewhere.
- `BAD_PARAM_VALUE` at warning level, as above.

## A test that keeps it closed

`params-do-something.test.mjs` renders every type twice — without, then with a
value of the shape each parameter declares — and fails on any parameter that
changes nothing. 54 known-inert parameters are baselined with reasons; a new
one fails the build, and a baselined one that starts working also fails, so
the list cannot rot into a list of excuses.

## Fixes

- **Every element type applies its `id`.** It was applied per component, which
  meant it could be forgotten — and was, by `video`, `table`, `nav` (never
  passed to its switcher), `polygon` (hardcoded `"hex"`) and `copy` (hardcoded
  `"#first"`, so every copy on a page shared an id). Applied once after
  dispatch, and covered by a test over all 36 types.
- **A bare number is read as pixels** for `radius`, `width`, `height` and the
  other length properties. `radius: 12` did nothing while `radius: "12px"`
  worked — and the documentation promised the opposite.
- **`transform` on an element is no longer discarded.** The mappers overwrote
  it with a design-node lookup, so a CSS transform written on an element was
  dropped.
- The schema no longer lists `Error` and `Set` among a type's components.
- The schema generator's brace scanner skips strings and comments. It read
  `//` inside a URL as a comment, so four mapper bodies never closed and ran
  to the end of the class, crediting their parameters to unrelated types.
