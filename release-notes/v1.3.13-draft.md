## `img.reveal` — a square-mask reveal on scroll

An image can now open from a square as it scrolls into view:

```js
{ type: "img", id: "shot", url: "/shot.jpg", alt: "…",
  reveal: { mask: "square", size: 0.3, duration: "1.2s", zoom: 1.12, offset: 0.2 } }
```

- It starts as a centred square, `size` × the frame's shorter side, with the
  image zoomed to `zoom`. Once the square rises `offset` of the viewport above
  the bottom edge, it opens to the full frame and settles to scale 1.
- **A true square.** `inset()` percentages resolve per axis, so on a tall or wide
  frame a percentage inset draws a rectangle. The insets are measured in px and
  re-measured when the frame resizes, without animating the re-measure.
- **It is never left shut.** The mask is applied only where it can be opened:
  reduced-motion visitors, and any environment without an
  IntersectionObserver (the jsdom prerender included), get the image unmasked.
- The zoom uses the `scale` property, not `transform`, so it composes with a
  transform the page sets instead of replacing it.
- `once: false` closes it again when it leaves; `easing` and `delay` are
  available too. An unknown `mask` is refused with a warning.
- Advertised by the schema (`img.reveal`, `{object}`), so `get_schema` and
  `validate_nodes` know it.

### Why a line and not a threshold

The first version opened at an intersection *ratio*, and in Chrome it never
opened: the browser measures the target clipped by its own `clip-path`, so a
closed square never shows more than its own share of the frame — about 8% at
`size: 0.3`. The trigger is therefore a line in the viewport (`rootMargin`,
threshold 0), which the square itself crosses.
