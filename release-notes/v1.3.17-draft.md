## `loop` — animation that runs forever, with no stylesheet

Anything that should move on its own used to need a `@keyframes` rule in a
`<style>` block — outside the page data, where the validator, the schema and
the agent tools cannot see it. A real page did exactly that for a slowly
drifting hatch pattern. Now it is an option on the element:

```js
{ type: "wrap", id: "hatch",
  keySet: [{ key: "backgroundImage", value: "repeating-linear-gradient(-45deg, #fff 0 1px, transparent 1px 7px)" }],
  loop: { keyframes: [{ backgroundPosition: "0px 0" }, { backgroundPosition: "98.99px 0" }], duration: 14000 } }
```

- Runs through the Web Animations API, forever (`iterations: Infinity`), with
  `duration`, `easing` (default linear), `direction` and `delay`.
- **Reduced motion: nothing moves.** In the prerender (no Web Animations) it is
  skipped, so static HTML is unaffected.
- Applied by the base class after a component's own `set()`, so it works on
  any component built on it; re-applying replaces the running loop rather than
  stacking another. Fewer than two keyframes is refused with a warning.
- **`video` keeps its own `loop`** (a boolean: restart the clip). Only an
  object is treated as an animation — the first version would have warned on
  every looping video.
- The schema credits `loop` to the 24 types where the element's options reach
  the component, and not to types whose mapper builds its own options — where
  it would be advertised and dropped.

The skill now says it plainly: no CSS in a Nodality page — no `<style>` rules,
no `@keyframes`; extend the library instead.
