# v1.3.24 — draft

> Draft only. Edit freely and paste into the GitHub release; nothing here is published.

## A morph is seen, however slow the first frame

`progressTimeline` measured a transition from the moment it was asked for.
Building both views and compiling the shader happen before the first frame,
and on a busy machine they took longer than the whole transition. The first
frame then computed t = 1 and the page arrived without any motion. The clock
now starts at the first frame, and one late frame can advance it by at most a
sixth of the journey (at least 50 ms). A slow device gets a slower transition
rather than none.

This was also why four browser tests failed whenever the release machine was
loaded ("never caught a mid-morph frame", "a rebuilt reversal actually
ANIMATES"). Under the same deliberate CPU stress, 1.3.23 failed 3 of 96 runs
of those suites and 1.3.24 passed all 96.

## `resprop` keeps an element's own value

- **A property given only at a breakpoint** fell back to `"initial"`
  everywhere else: the CSS initial value, not the element's. A font size set
  with `exact` became `initial` outside a breakpoint that named `fontSize`,
  and `display` would have become `inline`. It now falls back to what the
  element's options set, or to nothing, which hands the property back to the
  stylesheet.

  **Behaviour change:** a page that relied on the old `initial` will see that
  property return to the element's own value.
- **Each resize wrote every responsive property twice:** a reset to the
  default, then the breakpoint's value. A phone fires a resize per scroll
  gesture as its address bar moves. Each value is now written once, and only
  when it changes. A resize that changes nothing writes nothing.

## Videos keep their poster behind the frame

Browsers stop drawing the poster when `play()` starts, not when the first
frame arrives. In between, the element shows only its background. An
autoplaying loop that starts, or restarts, as it scrolls into view could
flash as an empty box. The poster is now also painted as the element's
background, sized like the frame (`objectFit`). `posterBehind: false` opts
out, for a clip with transparency.

## New options

- **`nav.brandLink`** — where the brand leads, e.g. `"/"`. The brand was never
  a link. Works in both bars and survives the code Des runs.
- **`colorScheme`** — CSS `color-scheme` on any element that takes the style
  options. A page that declares `<meta name="color-scheme" content="light
  dark">` (which keeps Chrome's auto dark mode off) can keep its native
  controls light with `colorScheme: "light"` on the controls themselves.
  **Not on whole sections:** Chrome darkens an element whose own scheme is
  light, so a light section is darkened again.

## The old two-view Switcher

`layout/switcher.js` is imported by nothing in the library, but it ships.
It rebuilt its content on every resize and appended a debug `<textarea>`
holding generated code to the page body. Now it swaps only when the matched
view changes, and appends nothing.

## Release tooling

- **`onlyPublish.sh` waits for the publish job, then the registry.** It used
  to exit 1 for releases that had worked (1.3.19, 1.3.21, 1.3.23): `npm view`
  answers from a cache, and 15 minutes from the tag push was too short. It
  now follows the workflow's "Publish to NPM" job, failing fast if that
  fails, and then polls the registry directly for up to 30 minutes.
- **Test output is no longer tracked.** `test-results/` and
  `playwright-report/` are ignored. Every run used to dirty the tree, and once
  blocked a `git stash pop` mid-release.

Tests: `resprop-own-value`, `transition-clock`, `nav-brand-link`,
`switcher-legacy`, and four poster tests in `video-loop`. Each fails on
1.3.23. The parameter probe's video fixture now has a poster, so
`posterBehind` has something to show.
