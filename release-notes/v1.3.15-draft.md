## Commerce for static pages

Eight element types sell through Shopify's Storefront Web Components, so a
prerendered Nodality page can take payments without becoming an app. The cart,
prices per market and checkout are Shopify's; the page stays static.

```js
const elements = [
  { type: "store", id: "store", domain: "https://shop.example.com" },   // first — see below
  { type: "product", id: "n01", handle: "suitcase-n01", children: [
      { type: "price", id: "n01-price", text: "€3,900" },
      { type: "variantPicker", id: "n01-options", text: "Size: Cabin · Check-in" },
      { type: "buy", id: "n01-buy", text: "Reserve yours", url: "https://shop.example.com/products/suitcase-n01" },
  ] },
  { type: "cart", id: "cart", theme: { background: "#F1EFEA", color: "#0E0F11", accent: "#0E0F11", accentText: "#F1EFEA" } },
];
```

| type | renders | static form (before the shop answers, prerendered HTML, no JS) |
|---|---|---|
| `store` | `<shopify-store>`, and loads Shopify's script once | — |
| `product` | `<shopify-context>`; its children go into the template | its children again, in their static form |
| `price` | `<shopify-money>` | `text` |
| `productData` | `<shopify-data>` for any Storefront field | `text` |
| `productMedia` | `<shopify-media>` | an `<img>` from `url` |
| `variantPicker` | `<shopify-variant-selector>` | `text` |
| `buy` | a button: add to cart and open it, or `mode: "buyNow"` | a link to the product on the shop (`url`) |
| `cart` | `<shopify-cart>`, themed through Shopify's `::part()`s | — |

- **The product is never missing from the page.** Every commerce element has a
  static form, and a product renders its children twice: live in the template,
  static in the placeholder Shopify shows until data arrives. That placeholder
  is what the prerenderer writes, so crawlers and readers without JavaScript
  get the product, its price and a working link to buy it. The static copy
  carries `-static` ids, so the page never holds a duplicate id once Shopify
  fills the template.
- **A product is a box** and takes layout options like a `wrap` (background,
  padding, width, …).
- **The cart theme** becomes `::part()` rules (dialog, buttons, line headings) in
  one `<style>` per cart, replaced on re-render. Values cannot break out of
  their rule.
- **`buy` ids are checked** before they reach the button's handler.
- Every option is described in `get_schema` with its shape, and
  `validate_nodes` checks them.

### The validator knows the order

A `product` looks for its `store` the moment it is attached, and Des attaches in
array order — so a product rendered before the store stays empty, and the only
sign was a console error in the browser. `validate_nodes` now warns:
`STORE_AFTER_PRODUCT` (with the path of the store to move) and `NO_STORE`.

`product` also joins the content-slot table: its content goes in `children`, and
`items` is reported as `WRONG_CONTENT_SLOT`.

## Agents can read a product, and cannot buy one

`agent-surface` takes `products: ["n01"]`. Each named product becomes a
read-only `get_product_<id>` tool returning what the product box shows — live
once Shopify has answered, the static copy before. There is no cart tool:
paying stays a human act on the shop's checkout. `validate_nodes` reports a
named product that does not exist (`UNKNOWN_PRODUCT`), and a surface with only
products is no longer `EMPTY_SURFACE`.

## Tests

`shop.test.mjs` (14): store and script, the live/static split (nested too), ids,
the product box, buy modes and refused ids, the cart theme and its escaping, the
slot and order checks, the agent tool, and a prerender. A negative control
(the `-static` rename disabled) fails the two id tests. The conformance probe
covers the new types; `buy.url`, `buy.store` and `productMedia.alt` are marked
not observable alone (they matter in the static form or one mode).
