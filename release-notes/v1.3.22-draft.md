## `nodality stage` versions the URLs it controls

A host that caches JavaScript by URL kept serving the previous
`/dist/lib.bundle.js` for a day after an upgrade, while the pages beside it
were new. That was sls3.cz's host, deployed on 1.3.21. `stage`, the step every
consumer's `upgrade.sh` runs, now writes `?v=<version>` into:

- **each page's importmap link to the bundle**, in every `.html` under
  `upload/`, subfolders included. An older stamp is replaced. Only inside
  `<script type="importmap">`, and only the link to the staged bundle;
- **the bundle's imports of the modules staged beside it, and theirs** (e.g.
  `../lib/raster-ops.js?v=…`). Otherwise a new bundle could load cached old
  copies of those, which is worse than either version alone. Every copy is
  stamped the same way, so each module still loads once.

Idempotent. `--no-cache-bust` turns it off.

## `gpos` on an image with one axis

1.3.21 fixed `gpos: { col }` writing `gridRow = undefined` (which a browser
reads as a grid line *name*, moving the element to an implicit row at the end
of the grid). It did so in `Animator.gpos`. Image wrote both axes itself and
kept the bug; it now goes through the same method.

Tests: `stage-cache-bust.test.mjs`, which runs `stage` for real against a
throwaway project (4 tests), and one image test. The stamping tests and the
image test fail on 1.3.21.
